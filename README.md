# hierfm

Код опытов к статье «Согласование вероятностных прогнозов предобученных моделей временных рядов по иерархии энергосистемы при короткой истории».

Статья проверяет два утверждения:

- Метод A даёт выигрыш согласования, даже если история ошибок покрывает только 1–4 недели. Метод сжимает ковариацию ошибок к априорной матрице, которая следует из устройства сети и погоды.
- Метод B возвращает интервалам верхних уровней заявленную вероятность. Метод восстанавливает связь сценариев между узлами, затем согласует сценарии.

## Запуск на кластере

Нужны Linux, python 3.13 и NVIDIA GPU.

```
git clone https://github.com/pluttan/hierfm.git && cd hierfm
make install install-models     # venv на python3.13, torch, Chronos-2, Chronos-Bolt, TimesFM 2.5 и 3.0
make install-moirai             # по желанию: Moirai-2, см. «Ограничения»
make cpuinfo GPU=0              # проверка: сокет, ядра, процессы, GPU и их привязка к сокетам
make experiment GPU=0 CPU=0     # вся программа опытов на карте 0 и процессоре 0
```

Готовые наборы `data/processed/ru` и `data/processed/europe` лежат в репозитории, около 90 МБ в сжатии zstd. Поэтому после `git clone` опыты запускаются сразу, без загрузки.

Пересборка наборов из открытых источников:

```
make download                   # сырые данные, около 2 ГБ, несколько часов
make data                       # сырые данные -> data/processed/{ru,europe}
```

## Выбор процессора

На машине два процессора, а работать нужно на одном. Makefile по умолчанию держит все стадии на процессоре 0 (`CPU=0`). Он запускает каждую стадию через `taskset` только на логических ЦП этого сокета. Число процессов оценки он берёт по физическим ядрам этого сокета и оставляет два ядра свободными.

- `CPU=1` переносит работу на второй процессор.
- `CPU=all` снимает ограничение.

GPU выбирайте на том же сокете. Столбец `CPU Affinity` в выводе `make cpuinfo` показывает, к каким ЦП подключена каждая карта.

## Выбор GPU

- `GPU=3` запускает работу на карте 3. Makefile ставит `CUDA_VISIBLE_DEVICES=3`, прогноз идёт одним процессом.
- `GPU=0,1` запускает работу на двух картах. Тогда прогноз идёт через `torchrun`, по процессу на карту.
- Если `GPU` не задан, Makefile берёт карты из `CUDA_VISIBLE_DEVICES`, а если его нет, то из `nvidia-smi`.

Каждый процесс берёт свою долю точек прогноза. Готовые файлы команда пропускает, поэтому прерванный прогон продолжается с места остановки. Для статьи хватит одного GPU: прогноз занимает меньше часа на A100 (оценка).

## Программа опытов

`make experiment` по очереди прогоняет три набора опытов. Набор описан файлом в `configs/suites/`. Каждый случай набора получает свой каталог `runs/<набор>/<опыт>/<случай>/`. После набора команда собирает все оценки в `runs/<набор>/all_scores.parquet` и `summary.md`.

Набор `ru` (ЕЭС России):

1. `main`: все модели, все методы согласования, все варианты связи сценариев, окна от недели до года, горизонты сутки и неделя.
2. `cold_start`: у узла есть только 7, 14, 28 или 91 день истории. Ограничение действует на вход модели и на окно ковариации.
3. `context`: длина входа модели от 256 до 8192 часов.
4. `model_size`: Chronos-Bolt tiny, mini, small и base.
5. `joint_scope`: совместный прогноз Chronos-2 и TimesFM 3.0 по группам ОЭС.
6. `weather`: модели с температурой без погоды и с фактической температурой вместо прогноза.
7. `ensemble`: усреднение квантилей нескольких моделей, затем согласование.
8. `prior`: вид априорной матрицы метода A, доля собственной ошибки узла и заведомо неверная матрица.
9. `samples`: от 50 до 1000 сценариев.
10. `seeds`: те же прогнозы с другими зёрнами случайных чисел.

Опыты 7–10 берут прогнозы из `main` и считаются только на CPU. Каждый опыт делит оценки на обычные дни, праздники и самые холодные дни.

Набор `europe` повторяет опыты 1, 2, 7 и 8 на европейской иерархии.

Набор `synthetic` выполняет исследование Монте-Карло на 135 синтетических сетях. Набор меняет силу общей погоды, силу погоды региона, число регионов и зерно. Набор идёт только на CPU.

Один набор или одну стадию можно запустить отдельно:

```
make suite SUITE=configs/suites/ru.yaml GPU=0
make forecast CONFIG=configs/ru.yaml MODELS=chronos2,timesfm25 GPU=0
make evaluate CONFIG=configs/ru.yaml JOBS=32
make report   CONFIG=configs/ru.yaml
```

Если python 3.13 на машине нет, укажите другую версию: `make install PYTHON=python3.12`.

## Проверка без данных и GPU

```
make install
make test       # согласованность сумм, вес сжатия, CRPS, перестановка Шааке, механизм узких интервалов
make smoke        # вся цепочка на синтетической сети из 13 узлов, около 20 секунд на CPU
make smoke-suite  # механика наборов: общий прогноз, холодный старт, ансамбль, около 2 минут
```

## Проверка моделей на GPU

После `make install-models` выполните `make smoke-gpu GPU=0`. Команда прогоняет каждую предобученную модель на синтетической сети отдельно и печатает по строке на модель:

- `ok`: модель отработала;
- `skip`: пакет модели не установлен;
- `FAIL`: модель упала. Журнал лежит в `runs-smoke-gpu-<модель>.log`.

Запустите эту проверку до настоящих данных. Она показывает, какие обёртки моделей нужно поправить.

## Стадии

| Стадия | Модуль | Где идёт | Результат |
|---|---|---|---|
| данные | `hierfm/prepare.py` | CPU | `data/processed/<name>/` |
| прогноз | `hierfm/forecast.py` | GPU | `runs/<name>/forecasts/<model>/h<H>/<origin>.npz`: квантили по всем узлам |
| оценка | `hierfm/evaluate.py` | CPU, пул процессов | `runs/<name>/scores/<model>_h<H>.parquet` |
| отчёт | `hierfm/report.py` | CPU | `runs/<name>/report/*.md`, `*.csv` |

Оценка выполняет для каждой точки прогноза такие шаги:

1. Берёт ошибки базовой медианы за окно перед точкой: 7, 14, 28, 91 или 365 дней.
2. Строит матрицу W каждого метода согласования.
3. Строит сценарии с нужной связью между узлами.
4. Согласует сценарии.
5. Считает MASE, CRPS, покрытие, ширину интервалов, energy score и variogram score по уровням.

## Модули

- `hierarchy.py`: дерево узлов и матрица суммирования S.
- `data.py`: набор данных на часовой сетке UTC. Верхние уровни команда всегда считает как сумму нижнего уровня.
- `models/`: Chronos-2, Chronos-Bolt, TimesFM 2.5, TimesFM 3.0, Moirai-2, сезонный наивный прогноз, градиентный бустинг на погоде.
- `covariance.py`: метод A. Априорная корреляция берётся из корреляции аномалий температуры или из блоков ОЭС. Вес сжатия считается по Schäfer & Strimmer (2005).
- `dependence.py`: метод B. Есть варианты `independent`, `schaake_hist`, `schaake_temp`, `schaake_err`, `gauss_copula`.
- `reconcile.py`: варианты `base`, `bu`, `ols`, `wls_struct`, `wls_var`, `mint_sample`, `mint_shrink`, `prior_shrink`, `prior_only`.
- `suite.py`: развёртка наборов опытов и сбор оценок.
- `metrics.py` и `stats.py`: метрики, тест Диболда–Мариано с поправкой HLN, MCB.

## Данные

Ресёрч, данные и обоснования решений описаны в `docs/research/README.md`.

| Набор | Узлы | Период | Особенности |
|---|---|---|---|
| `ru` | 81: ЕЭС, 7 ОЭС, 67 субъектов АТС и остатки ОЭС | 2017-01 .. 2026-09 | АТС не публикует выходные и праздники. Измерено 67,6 % ячеек нижнего уровня. |
| `europe` | 22: Европа, Франция, Германия, Дания и их зоны | 2020-01 .. 2026-09 | Пропусков нет. |

Приняты такие решения:

- Выходные России заполняются только по прошлым дням (`causal`). Метрики считаются только по измеренным ячейкам, маску даёт `observed.parquet`.
- Узел с единственным ребёнком сворачивается в лист. Так ОЭС Востока и её остаток не дают двух одинаковых строк в S.
- Тест обоих наборов идёт с 2025-10-01 по 2026-09-22, после выхода Chronos-2.
- Температура попадает в набор, только если покрывает 95 % последних двух лет. Факт берётся из NASA POWER, прогноз IFS из Open-Meteo с 2024-10. Вся погода скачивается за 20–30 минут. Оба набора, `ru` и `europe`, получают одинаковые источники.
- Прогноз температуры из Historical Forecast API в набор не идёт. Этот источник склеен из первых часов каждого прогона и близок к факту.
- Вес сжатия метода A учитывает автокорреляцию часовых ошибок через число дней в окне. Варианты `mint_shrink_neff` и `prior_shrink_raw` разделяют вклад поправки и априорной матрицы.

`configs/check-ru.yaml` проверяет всю цепочку на настоящих данных России: две недели, сезонный наивный прогноз, около 30 секунд на слабой машине.

## Ограничения

- `uni2ts` (Moirai-2) требует `numpy~=1.26` и `torch<2.5`. Для python 3.13 таких сборок нет. Поэтому `make install-moirai` ставит пакет без его зависимостей. Если модель не запустится, прогноз её пропустит.
- Веса TimesFM 3.0 распространяются по некоммерческой лицензии. Для статьи это допустимо. В совместном режиме модель берёт не больше 32 рядов за проход, поэтому для России нужен режим по группам ОЭС.
- Обёртки моделей сверены с исходниками пакетов, но на GPU ещё не запускались. Первым шагом на кластере выполните `make smoke-gpu`.
